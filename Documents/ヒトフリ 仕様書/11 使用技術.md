# 使用技術

担当は全員。基盤コードは髙橋が最初にまとめて用意する。方針は「Unityの標準機能で書ける範囲で書く。迷ったら使わない」で、難しい仕組みは入れない。

## 決まっていること

| 種類 | 使うもの | 用途 |
| --- | --- | --- |
| エンジン | Unity 6.3 LTS、URP | プロジェクトルールの通り |
| 提出先 | WebGL(unityroom) | 1日目に一度、空のプロジェクトで提出まで通す(増永) |
| 非同期処理 | UniTask | 演出の待ち時間、時間差の湧きなど。コルーチンの代わりに使ってよい |
| 入力 | Input System | ゲームパッドとキーボード・マウスの両対応。Input Actions のアセットは髙橋が用意する |
| カメラ | Cinemachine | 通常の見下ろしと斬り抜け演出の切り替え(髙橋) |
| UI | uGUI、TextMeshPro | 画面まわり(増永) |
| エフェクト | Particle System | 残光、軌跡、光の粒など |
| 担当間の連絡 | C#標準の event | 基盤コードの GameEvents にまとめる |

### 使わないもの

- **R3:** イベントはC#標準の event で書く
- **DIコンテナ(VContainer、Zenjectなど):** 規模に対して仕組みが重い
- **VFX Graph:** WebGLでは動かないので、エフェクトは Particle System で作る
- **UniTaskのスレッド切り替え:** WebGLはマルチスレッドに対応しないので、スレッドプールへ移す機能は使わない
- **Addressables:** 動的ロードが必要なら Resources で足りる

## 任せること(各担当)

- コルーチンとUniTaskのどちらで書くか
- Shader Graph でシェーダーを作るかどうか
- Tweenライブラリ(DOTween、LitMotionなど)を使うかどうか。入れる場合は1種類に絞り、入れる前に朝会で共有する

上の表にないパッケージやアセットを入れたいときは、入れる前に朝会かNotionで共有し、何に使うかを1行残す。
