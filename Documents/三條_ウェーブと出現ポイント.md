# ゲーム進行の骨組み・ウェーブ・出現ポイント

対象プロジェクトは `C:/Users/sanjo/Ioa/gamejam/IoAGameJam-2026-11` です。既存の3体を時間差で出現させ、管理対象の全員が場外へ落ちると次のウェーブへ進む骨組みを実装しました。開始と終了は既存のGameEventsを使います。

## 最初に確認する

1. Unity上部の `Hitofuri > Sanjo > Open Enemy Wave Test` を選びます。
2. `Assets/_Project/Scenes/Dev/Sanjo/EnemyWaveTest.unity` が開いたら、GameタブでScaleを1xにしてPlayを押します。
3. 最初の約0.6秒後にWaveStarted(1)が通知され、影3体が0.7秒間隔で出現します。既存のポップアニメーションも再生します。
4. 上部にウェーブ番号、状態、Pending（未出現の予定数）、Alive（管理中の生存数）、Started／Clearedの通知回数が表示されます。
5. 出現中のキャラを拡大するには `Focus last spawn`、全体へ戻るには `Overview` を押します。
6. `Throw spawned enemies (test)` で、現在出現している敵を場外へ飛ばします。このボタンは確認用です。実際のLaunch→落下→EnemyFellを通し、WaveClearedを直接発行しません。
7. PendingとAliveが両方0になるとWaveClearedが1回だけ通知され、約2秒後に次のウェーブが始まります。出現途中に投げた場合、残りの敵が後から出るため、もう一度投げてください。
8. 5ウェーブを終えるとCompletedで止まります。勝利をGameOverとして扱いません。

`Next wave` はクリア後の待ち時間を省く確認用の操作です。未クリアのウェーブを飛ばしません。`GameOver test` は共有のPlayerDamaged(0)を発行し、以後の出現と進行を止めます。`Restart test` は敵とB担当のウェーブ進行だけを初期化します。プレイヤーHP・入力・スコアのリセットは各担当の所有です。

この確認シーンには本番プレイヤーや追跡AIはありません。キャラの出現とポップ、ウェーブの通知と進行、実際の落下による完了を確認するシーンです。キャラの輪郭が分かるよう、このシーンだけ草Rendererを非表示にしています。元のマップPrefabの草は変更していません。

## 出現場所を変更する

SceneのHierarchyで次を展開します。

```text
WaveGameSystem
├─ SpawnPoints
│  ├─ EdgeEast
│  ├─ EdgeNorthEast
│  ├─ EdgeNorth
│  ├─ EdgeNorthWest
│  ├─ EdgeWest
│  ├─ EdgeSouthWest
│  ├─ EdgeSouth
│  ├─ EdgeSouthEast
│  ├─ Center1
│  ├─ Center2
│  ├─ Center3
│  └─ Center4
└─ SpawnedEnemies  （実行中の生成先）
```

各ポイントのTransformをScene上で動かすと、出現位置を変えられます。GizmosをONにすると名前・向き・ポイントを表示します。選択したポイントには候補範囲の球も表示します。

- `Areas`：中央、北、東、南、西。斜めのポイントは隣接する2方角に所属します。Unityの+Xが東、+Zが北です。
- `Radius`：ポイント周辺で安全な候補を探す範囲。初期値は1.5mです。
- 矢印：出現時の初期の向き。既定では島の中央を向きます。GameContext.PlayerTransformがあれば、その時の主人公を向きます。

外周ポイントは島のMeshColliderを調べて、縁より内側へ配置しています。中央の4点も実際の床へ投影しています。非対称な島なので、中央ポイント群の中心はワールド原点と一致しません。座標一覧は同梱の「ウェーブ-出現ポイント座標.tsv」にあります。

両方のシーンで同じ配置を使う場合は `Assets/_Project/Prefabs/WaveGameSystem.prefab` を開いてポイントを編集します。特定シーンだけ変える場合は、そのScene内のインスタンスを編集します。シーンの変更をPrefabへApplyする場合は、共有範囲が両方へ及ぶことを確認してください。

床のない場所、床の縁ぎりぎりの候補、主人公から3m未満、同じスポナーが管理する敵から1.6m未満の候補では出現させません。候補を変えて再試行し、全候補が塞がっている場合は予定を消費せず待ちます。10秒間出せなければFaultedになり、確認画面とConsoleに理由を表示します。出せなかった敵を消化済みとしてクリアしません。

## GameEventsでの連携

| 通知 | 発行条件 |
| --- | --- |
| `GameEvents.RaiseWaveStarted(number)` | そのウェーブの出現予定をセットし、開始状態になった時。番号は1始まり |
| `GameEvents.RaiseWaveCleared(number)` | 全予定の出現が完了し、そのスポナーが出した全員の落下を確認した時 |
| `GameEvents.GameOver` の受信 | 未出現の予定と次ウェーブへの進行を停止 |

WaveClearedはEnemyFellの通知チェーンが終わった後のLateUpdateで流します。落下のスコア集計などが通知途中のまま次のウェーブへ進むことを避けています。

```csharp
void OnEnable()
{
    GameEvents.WaveStarted += OnWaveStarted;
    GameEvents.WaveCleared += OnWaveCleared;
}

void OnDisable()
{
    GameEvents.WaveStarted -= OnWaveStarted;
    GameEvents.WaveCleared -= OnWaveCleared;
}

void OnWaveStarted(int number)
{
    // 自分の担当するウェーブ表示や演出を更新する
}

void OnWaveCleared(int number)
{
    // 銘を選ぶ画面を出す場合などは共有の停止を要求する
    // TimeController.RequestPause(this);
    // 選択完了時に TimeController.ReleasePause(this);
}
```

自動進行がONなら、共有のPauseが解除された後に残りの待ち時間を進めます。敵担当のクラスをUI側から直接変更する必要はありません。WaveGameSystemのWaveControllerにあるAuto AdvanceをOFFにすると、自動では次へ進みません。

最後のWaveCleared(5)でもGameOverは発行しません。全ウェーブ完了の扱いはCompleted状態と最後のWaveClearedです。勝利の結果画面への接続は担当側がこの通知を受けて行う形です。Sharedに新しい勝利イベントを勝手に追加していません。

## 完了判定と異常系

進行状態は `Ready → Spawning → WaitingForEnemies → Intermission → 次のSpawning` です。最後の完了はCompleted、被弾による終了はGameOver、出現不能や予定外の消失はFaultedに分けています。

EnemyFellInfoには発行元の敵参照がないため、スポナーは登録済みの敵のFallen状態を照合して残数を更新します。無関係な敵の落下や、単に同じイベントを再送しただけでは自分の残数を減らしません。

外部コードが場外落下を通さずに管理中の敵をDestroyすると、Faultedとして停止します。単なる削除を撃破として数えて、誤ってWaveClearedを流さないためです。プーリングを将来入れる場合は、この生存管理との接続も合わせて変更してください。

RestartRunはB担当の進行と管理中の敵を初期化する口です。HP、入力、UI、スコアを初期化する全体のリトライ処理は各担当の状態と別途つなぎます。

Unity 6000.3.22f1の実際のPlayモードで46項目を確認しました。5ウェーブの全30体、開始と終了の各1回通知、最後の落下より後の完了通知、未出現予定が残る時の完了抑止、中央・外周の出現、プレイヤーとの間隔、共有Pause、出現不能からの復帰、場外床なし時の停止、外部Destroyの検知、GameOverによる予定中止、WaveStartedの通知中にGameOverが起きた場合、再開を含みます。
