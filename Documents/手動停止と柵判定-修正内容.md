# 手動停止・柵との重なり・旧主人公の置換

2026年11月12日。対象: IoAGameJam-2026-11、B担当のスクリプト。

## 今回の修正

### 1. 自動検証を途中で止めても、次のPlayへ残さない

検証スクリプト8本の `OnState` で `ExitingPlayMode` を処理するようにした。

- `EditorApplication.update` から検証の更新処理を外す。
- `GameEvents`、`EnemyMotionEvents` などへの購読を外す。
- 検証用Gamepad・Mouseを削除し、変更した入力設定を戻す。
- 検証が要求した一時停止と、差し替えた共通状態を戻す。
- 実行中フラグ、IEnumerator、シーンの参照、SessionStateのKEYを解除する。

後始末は各クラスの `Cleanup()` へ集約した。通常完了の `Finish()` からも同じ後始末を呼ぶ。手動停止では結果を失敗として保存したり、`EditorApplication.Exit` でUnityを閉じたりしない。通常の `EnteredPlayMode` で検証を開始する処理は維持した。

対象は `EnemyActionPlayModeChecks`、`EnemyLaunchPlayModeChecks`、`EnemyPursuitPlayModeChecks`、`EnemyReviewRegressionChecks`、`EnemyWavePlayModeChecks`、`InkReviewPlayModeChecks`、`LatestPlayerHandoffChecks`、`PlayerIntegrationPlayModeChecks`。

### 2. 柵に最初から重なる敵も、柵を通過させない

`Enemy.ObstacleDistance` で、CapsuleCastの前に同じ形の `Physics.CheckCapsule` を行う。開始位置ですでに柵と重なっている場合は、移動可能距離を0にする。

追跡では移動要求を拒否し、吹き飛びではその場で止める。吹き飛び中のColliderは無効になっているが、形の定義値から調べるので検査できる。すでに重なった配置を自動で外へ押し出す処理ではない。

### 3. 出現時は足元の球だけでなく、全身のカプセルを調べる

`EnemySpawner.HasClearance` に、出現後のカプセル全体の検査を追加した。上半身だけが柵や梁に重なる配置も拒否する。

実際に出す向きを決めてから、Colliderの中心・高さ・半径・方向・Prefabと親のスケールを使って検査する。形の計算は `EnemyCapsuleGeometry` にまとめ、移動側と出現側で別々の半径を持たないようにした。

### 4. 生成処理で旧主人公を見つけた場合も置換する

`PlayerIntegrationAssetSetup.InstallMain` は、PlayerControllerがあるだけで接続完了とせず、正規の `Player.prefab` へ接続する。

`LatestPlayerHandoffSetup` の置換では、位置・向き・親・スケールに加え、他のシーン部品が持つGameObject・Transform・同種Componentの参照を新主人公へつなぎ直す。UIの主人公参照や被弾対象も引き継ぐ。

対応する子部品が新主人公にない場合は、旧主人公を消さず、対象の参照先を示して止める。参照を失った状態で黙って保存しないため。

## どこを変更したか

すべて `Assets/_Project/Scripts/` 内。

| 場所 | 役割 |
| --- | --- |
| `Enemy/Enemy.cs` | 開始位置の重なり検査 |
| `Enemy/EnemyCapsuleGeometry.cs`（新規） | 移動・出現で共有するカプセル形状の計算 |
| `Game/EnemySpawner.cs` | 向きを含めた全身の出現検査 |
| `Game/` の上記8本の検証スクリプト | Play終了時の後始末 |
| `Game/PlayerIntegrationAssetSetup.cs` | 既存主人公が旧Prefabでも正規Prefabへ接続 |
| `Game/LatestPlayerHandoffSetup.cs` | 置換前の参照を点検して引き継ぐ |
| `Game/EnemyCheckCancellationChecks.cs`（新規） | 8本の手動停止と通常Play再開の検証 |
| `Game/EnemyObstacleSafetyChecks.cs`（新規） | 重なり・出現・主人公置換の検証 |

## 確認内容

手動停止の検証は、`EditorApplication.ExitPlaymode()` で実際の終了遷移を起こした。購読解除の点検はドメイン再読み込みより前に行い、再読み込みで勝手に状態が消えたことを成功扱いにしていない。その後、KEYを設定せず通常のPlayへ入り、検証の再開・仮想入力・更新コールバックがないことを点検した。

柵の検証は、実Collider同士の `Physics.ComputePenetration` で重なりを確認した配置を使った。出現検査は「上半身」「大きい半径」「親の拡大」「中心のずれ」「横向きのカプセル」の5条件を確認し、障害物を退けると同じ場所から出現できることも確認した。

主人公置換では、外部のPositionConstraintからのTransform参照、UIのGameObject参照、被弾対象のPlayerHealth参照、親と位置の維持、繰り返し接続しても主人公が増えないことを確認した。現在保存されている本番・確認シーンのPrefab参照も点検した。

置換できない子部品への参照を意図的に作った場合も、旧主人公と既存参照が残り、新主人公が重複して残らないことを確認した。

最終結果:

| 確認 | 結果 |
| --- | --- |
| 8本の検証を停止→通常Playへ再開 | 127項目 PASS |
| 開始重なり・全身出現検査・主人公参照の点検 | 28項目 PASS、置換拒否時の参照保全もPASS |
| 既存の5ウェーブと異常系 | 46項目 PASS |
| 前回の復帰待ち・Collider寸法の回帰確認 | 27項目 PASS |
| 実主人公の斬り戻し→落下→ウェーブ終了 | 30項目 PASS |

変更前後のハッシュも照合し、既存シーン・Prefab・Tuning・共有基盤・主人公・Packages・ProjectSettingsに変更がないことを確認した。

検証時の配置や値はPlay中または未保存の確認シーンだけで作り、既存のシーン・Prefab・Tuningアセットへ保存していない。共有のGameEvents・ILaunchable・主人公のコードも変更していない。コミット・プッシュは実施していない。
