# 共同作業で使う吹き飛びとイベントの契約

対象は `C:/Users/sanjo/Ioa/gamejam/IoAGameJam-2026-11`。現在のSharedとPlayerの実装を確認したうえで、各担当が同じ窓口を使えるように整理したものです。

## 開始の指示と、起きたことの通知

```text
プレイヤー側が初速を計算する
    ↓
ILaunchable.Launch(velocity, slashId) を1回呼ぶ
    ↓
敵が初速を保持し、吹き飛び・光の蓄積を開始する
    ↓
プレイヤー側が GameEvents.RaiseEnemyHit(info) を1回呼ぶ
    ↓
演出・集計などの各担当が EnemyHit を受け取る
```

現在のPlayerController.ApplyHitはすでにこの順番です。**EnemyHitは吹き飛びの命令ではなく、命中した結果の通知です。EnemyHitの受信側でLaunchをもう一度呼ばないでください。** Enemy自身や姿勢通知の受け手も、結果通知からLaunchを呼び直しません。

## 各担当の持ち物

| 持ち主 | その担当だけが更新するもの | 他担当へ渡す窓口 |
| --- | --- | --- |
| プレイヤー担当 | 命中判定、初速計算、一振りの番号、プレイヤーHP | ILaunchableへの呼び出しとGameEvents.EnemyHit／PlayerDamaged |
| 敵・ゲーム進行担当 | 敵の速度、摩擦、光の蓄積、停止と落下、受け取ったslashIdの保持 | ILaunchableの参照用プロパティとGameEvents.GlowChanged／EnemyTeetered／EnemyFell／GameOver |
| 演出・UI・集計担当 | 自分の演出、表示、集計、結果画面 | 共有GameEventsの購読 |

初速に掛けるWeightとGlowMultiplierはプレイヤー側で使い、敵側で二重に掛けません。MeiStatsの最終倍率は使う時に読みます。敵の姿勢を変えるクラスと、敵のRootを移動させるクラスも分けています。

## 共有GameEventsを見て連携する

| イベント | いつ発行するか | 受け取り側の用途 |
| --- | --- | --- |
| `EnemyHit(EnemyHitInfo)` | 呼出し側がLaunchした後 | 命中演出、命中の集計。Launchの再実行には使わない |
| `GlowChanged(ILaunchable, float)` | 敵の蓄積が変わった時。リセット時は0 | 対象の見た目や表示を更新する。割合は0〜1 |
| `EnemyTeetered(ILaunchable)` | 敵が縁で止まり、踏みとどまりを始める時 | 対象の揺れ・音など |
| `EnemyFell(EnemyFellInfo)` | 場外へ落下した時。破棄前に1回 | slashIdで一振りを集計し、Positionで落下演出を出す |
| `GameOver()` | PlayerDamagedの残りが0以下になった時。1ラウンドに1回 | 各担当が自分の入力・移動・姿勢・画面を終了状態へ移す |

GameEventsとILaunchableは既存の署名を維持します。スコア担当がEnemy型を直接参照したり、プレイヤー担当が個々の敵のアニメーションクラスを呼んだりする必要はありません。

EnemyFellInfoには敵オブジェクト自体は入っていません。破棄後も使う情報は通知で渡されたSlashIdとPositionを使い、破棄予定の敵に保存し直して読ませる形にはしません。

## 購読側の最小例

以下は敵本体に付ける、命中通知の受け取り例です。自分の担当する演出だけをハンドラー内へ追加します。

```csharp
using UnityEngine;

public sealed class EnemyHitNoticeExample : MonoBehaviour
{
    ILaunchable target;

    void Awake() => target = GetComponent<ILaunchable>();
    void OnEnable() => GameEvents.EnemyHit += OnEnemyHit;
    void OnDisable() => GameEvents.EnemyHit -= OnEnemyHit;

    void OnEnemyHit(EnemyHitInfo info)
    {
        if (target == null || !ReferenceEquals(info.Enemy, target)) return;
        // info.SlashId、info.Velocity、info.Frontnessを読んで自分の演出を更新する。
        // ここでtarget.Launchは呼ばない。呼出し側がすでに実行している。
    }
}
```

スコアなど全体を集計するクラスは対象で絞らず、EnemyFellなどを購読します。購読はOnEnable、解除はOnDisableで必ず対にします。オブジェクトを再表示するたびに購読が重複する形にしません。

## EnemyMotionEventsの範囲

EnemyMotionEventsはB担当内の姿勢通知です。SharedにまだないLaunched、MotionUpdated、Falling、Recovered、Resetだけを補います。他担当の共通の命中・蓄積・落下通知を置き換えません。

EnemyActionAnimationはこの通知とGameEventsを購読して、対象が自分に一致した時だけ姿勢や材質を更新します。LaunchedやMotionUpdatedを受け取る側でも、再びLaunchを呼ばないでください。速度の所有者はEnemyで、再生側は通知された速度を読みます。

## 今後追加するゲーム進行と出現場所

ウェーブ、群がり、出現場所の実装でも、ゲーム状態の所有者と演出の受け取り側を分ける方針を継続します。WaveStarted／WaveCleared／SwarmCountChangedは、それぞれの状態を実装した時に実際の変化に合わせて発行します。通知だけを先に流してゲームが進んだことにはしません。

出現位置・出現間隔・敵の種類は出現を管理する側の設定に置き、アニメーション側へ座標やウェーブ進行を埋め込みません。今回の整理ではウェーブや出現位置の新しい実行処理は追加していません。

今回変更したのは、この連携説明書とEnemy／EnemyMotionEventsのコードコメントです。実行処理と公開APIは変更していません。既存の吹き飛びは前回のPlayモード43項目の検証対象です。
