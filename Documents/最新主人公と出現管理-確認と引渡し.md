# 最新主人公・出現管理・引渡しの確認

確認日: 2026年11月11日。対象: `IoAGameJam-2026-11`。

## 現在の結論

GitHubから入った実際の `Player.prefab` で、敵の追跡、接触ダメージ、刀設置、斬り戻し、吹き飛び、場外落下、ウェーブ終了まで動作する。主人公の移動・攻撃処理とアニメーションは主人公担当の既存実装を使用している。今回、その処理を代替する主人公スクリプトは追加していない。

以前の確認シーンは簡易形状の `PlayerIntegrationActor.prefab` を参照していた。今回、本物の `Player.prefab` を直接参照する状態に接続し直した。元の主人公Prefab・主人公スクリプト・共有インターフェースは変更していない。

基本戦闘の接続を他担当へ渡せる状態になった。一方、銘の本番実装と演出サービスの登録、共有mainへの統合までが完了した状態ではない。

## まず実際に見る方法

1. Unityでこのプロジェクトを開く。
2. 上部メニュー **Hitofuri → Sanjo → ステージ・出現管理** を開く。
3. ウィンドウ内の **最新主人公を観察** を押す。
4. Unity上部の ▶ を押す。
5. 「第一波」の表示後に3種類が同時に出現する。刀を持っている間は全種類が主人公へ向かい、近づくと自動攻撃する。

操作は **WASDで移動、左クリックを押して刀を置き、押したまま移動し、離して斬り戻す**。UIボタン上のクリックでは刀を設置しない。

観察用シーンは接触ダメージを初期状態では止めている。画面の **接触ダメージ** ボタンで有効にすると、本物の `PlayerHealth` が被弾し、残り0でゲームオーバーになる。安全観察中も敵の自動攻撃自体は動く。

刀を置くと、刀の誘引範囲内の灯喰らいが刀へ向かう。影と盾持ちは主人公を追い続ける。灯喰らいの見た目には作成済みの人狼モデルを使っている。斬り戻すと灯喰らいも主人公へ戻る。

**正面ガード確認** ボタンは向きを固定した練習配置へ切り替える。これはガード判定を見やすくする専用配置で、通常観察中の敵AIとは区別する。現在の共有仕様は正面ガードで吹き飛びを完全に防ぐもの。0.2倍で飛ぶ仕様ではない。同じ斬撃は盾の後ろの敵へ届く。

## 1体で最初から最後まで見る方法

Playを停止してから、管理ウィンドウの **1体の通し確認** を開く。

1. Playすると、東の岬付近の主人公へ影が近づく。
2. そのまま待つと自動攻撃し、接触で被弾する。
3. 左クリックを押したままDで右へ約8m移動して、左クリックを離す。
4. 斬り戻しが影に当たると、影が白く光り、自前の軌道で飛び、岬の先で落下する。
5. 残りが0になり、1波の終了表示になる。

このシーンは接触ダメージが有効。放置するとゲームオーバーになる。再挑戦でやり直せる。

ゲーム画面側には「最初から」「この波から」「タイトルへ」の導線がある。タイトル画面そのものは作成していない。タイトル担当が `GameScreenEvents.TitleRequested` を購読するまで、タイトル導線は「準備中」で無効になる。

## 出現管理ツールの使い方

設定を変えるときはPlayを停止する。Play中は編集を止め、現在の状態を見る用途にする。

### ウェーブ設定

- **編集する出現計画**: 現在の `EnemyWavePlan` アセット。別の計画を選んだ場合は、**この計画を現在のシーンに設定** を押すと `WaveController` と `EnemySpawner` の両方へ設定する。その後シーンも保存する。
- **編集する波**: 対象の波番号。
- 各グループの **敵のPrefab／出す数／開始を遅らせる秒数／1体ごとの間隔／使う出現区域** を編集できる。
- グループと波を追加・削除できる。変更はUndo対応。
- **待ち時間と安全距離**: 開始待ち、波の間隔、主人公や敵との最低距離、端の余白、出現再試行など。
- **出現計画を保存**: アセットへ保存する。同じアセットを使うシーンすべてに反映される。

区域の対応は `Center=中央 / North=北 / East=東 / South=南 / West=西 / AnyEdge=外周 / Anywhere=全部`。グループと出現ポイントの区域が重なる場所から候補を探す。

観察用 `ThreeEnemyReviewPlan.asset` は3種類を同時に出すための計画。本番5波は `EnemyWavePlan.asset`、1体の通し確認は `PlayerIntegrationRoutePlan.asset` を使う。観察用の数を変えても本番の出現数は変わらない。

### 出現ポイント

- ポイント追加、有効／無効、区域、周辺に出す半径、座標を編集できる。
- **選択** でHierarchy上のポイントを選択し、Sceneビューで位置を確認する。
- **真下の床へ高さを合わせる** で床面へ置く。
- **出現ポイントのシーンを保存** で座標と有効状態を保存する。計画アセットの保存とは別。
- 床がない場所、主人公に近すぎる場所、柵に重なる場所では出現しない。候補が見つからない場合は再試行し、制限時間を超えると進行を止めて原因を表示する。

### 接続・引渡し確認

**現在の接続と出現データを点検** で、主人公が1体か、本物のPrefabか、床上の出現点があるか、区域に対応するポイントがあるか、敵の設定があるか、進行と出現が同じ計画を使うかを点検できる。点検は動作保証の代わりではなく、設定ミスを見つけるもの。

Play中は銘の供給元、威力倍率、光蓄積倍率、刀の誘引倍率、演出サービスの登録状態も表示する。`DefaultMeiStats` の表示は銘の既定値が使われていることを示す。

## 共同作業の接続点

吹き飛ばす命令は、共有インターフェース `ILaunchable.Launch(Vector3 velocity, int slashId)`。主人公側が初速を計算して呼ぶ。その後 `GameEvents.EnemyHit` は結果の通知として発行される。敵はこの通知から再びLaunchしない。これにより二重の吹き飛び・光蓄積を防ぐ。

実際の順序は `WaveStarted → SwordPlanted → SlashStarted → GlowChanged → EnemyHit → EnemyFell → WaveCleared`。`GlowChanged` が `EnemyHit` より先なのは、Launch内で蓄積を更新してから、主人公が結果を通知するため。

敵は最後の `slashId` を落下まで保持し、`EnemyFellInfo` で渡す。スコアや一振り最多は、そのイベントを受け取る担当側で処理する。ウェーブ管理は自分が出した敵の落下を照合して残数を減らす。

購読は `OnEnable` の `+=`、解除は `OnDisable` の `-=`。発行は `GameEvents.Raise...`。共有基盤のシグネチャを変更する独自イベントは追加していない。敵内部の姿勢通知は既存の `EnemyMotionEvents` を使う。
