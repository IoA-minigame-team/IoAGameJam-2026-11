# はじめに

## このガイドについて

他の人の担当に関わる作業をするとき、「何に気をつけるか」「どう実装するか」を確認するための資料。何を作るかは企画書と仕様書、どうつなぐかはこのガイドを見る。

| いつ読むか | 読むところ |
| --- | --- |
| 開発初日に一度 | 「はじめに」を最後まで |
| 他の人と関わる作業を始める前 | 自分の名前の章 |
| コードを書いていて呼び方に迷ったとき | 基盤コード辞書 |

| 担当 | 人 | 自分の章 |
| --- | --- | --- |
| A プレイヤー | 髙橋(カピ) | 髙橋の連携 |
| B 敵とゲーム進行 | 三條 | 三條さんの連携 |
| C 演出基盤とUI | 増永 | 増永さんの連携 |

## 守る3つの原則

- **他の人のクラスを直接呼ばない:** 起きたことは GameEvents で知らせ、知りたい人が受け取る。例えば敵が落ちたとき、三條さんはスコアのクラスを呼ばずに「敵が落ちた」を流すだけにする
- **値を書き換えるのは持ち主だけ:** 他の人の値は読むだけにする。例えば光の蓄積は三條さんだけが書き換え、増永さんは見た目に使うだけ
- **相手が未完成でも止まらない:** 基盤コードの形さえあれば、相手の中身がなくても呼べる。待つ代わりに仮の値やダミーで進める

## 基盤コードについて

イベントとインターフェースなど、3人をつなぐコード(基盤コード)は髙橋が開発初日にまとめて用意し、`Scripts/Shared/` に置く。各自はそれを呼ぶか実装するだけでよい。

基盤コードに足りないものがあれば、自分で書き換えずに髙橋に相談する。小さな追加ならその日のうちに入れる。

## 毎日の流れ

1. **朝会(10分):** 昨日やったこと、今日やること、誰かを待っていることの3つだけ言う
2. **昼の統合:** 各自のブランチを main に入れ、三條さんが GameScene で通しで動くか確認する
3. **夜の試遊(20〜30分):** 3人で同じビルドを触り、気づいたことをNotionのタスクに1行ずつ書く

| 日 | 目標 |
| --- | --- |
| 1日目 | 基盤コードの用意(髙橋)、WebGLビルドの通し確認(増永)、仮の敵1種(三條) |
| 2日目 | コアループを通しで遊べるようにする。夜に面白さの判定 |
| 3〜4日目 | 敵3種と銘を入れる |
| 5日目 | 演出と画面を磨く。夜に機能凍結 |
| 6〜7日目 | 調整、バグ修正、提出 |

## ファイルとGit

フォルダ構成、命名、作業ルールはNotionのUnityプロジェクトルールに従う。『ヒトフリ』で追加する決めごとは次の通り。

```
Assets/_Project/Scripts/
  Shared/    … 基盤コード(髙橋)
  Player/    … 髙橋(時間制御を含む)
  Enemy/     … 三條
  Game/      … 三條(ウェーブ、ステージ)
  Mei/       … 増永
  Feedback/  … 増永
  UI/        … 増永
```

| ファイル | 担当 |
| --- | --- |
| GameScene | 三條 |
| TitleScene、ResultScene | 増永 |
| 主人公と刀のPrefab | 髙橋 |
| 敵とステージのPrefab | 三條 |
| UIとエフェクトのPrefab | 増永 |

- **GameScene への配置は三條さんに頼む:** 他の2人は自分のPrefabを更新し、試すときは `Scenes/Dev/自分の名前/` のシーンを使う
- **main への取り込みは1日2回(昼と夜):** 長く離すほど統合が苦しくなる

## 困ったとき

- 他の人のファイルを直したくなったら、自分では触らずに持ち主に頼む
- 呼び方が分からなければ基盤コード辞書を見て、それでも分からなければ髙橋に聞く
- 15分考えて進まなければ、朝会を待たずにNotionかチャットで相談する
