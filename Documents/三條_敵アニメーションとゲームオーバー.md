## 敵本体から呼ぶ例

既存または今後のEnemyクラスに、見た目の参照を1つ渡します。防御成立の判定やダメージ処理はEnemy側に残します。

```csharp
[SerializeField] EnemyActionAnimation actions;

void BeginGuard() => actions.SetDefending(true);
void EndGuard() => actions.SetDefending(false);
void BeginAttack() => actions.PlayAttack();
void ShowSpawn() => actions.PlaySpawn();
```

出現はPrefabを有効にした直後にも自動再生します。`PlayAttack()` は見た目だけなので、命中タイミングや攻撃判定は敵本体から別途処理してください。`SetDefending(true)` も攻撃無効化を決めません。盾の正面判定 `IsShieldFacing` は今後のEnemy実装が持つ役目です。

## ゲームオーバーの接続

`Assets/_Project/Scenes/Main/InGame.unity` には、UnityエディタのAPIで `GameOverSystem` を1個追加済みです。他の既存オブジェクトはそのままです。このシーンの変更前データも差分バックアップZIPに保存しました。

処理の経路は次のとおりです。

`PlayerHealth → GameEvents.PlayerDamaged(remaining) → GameOverController → GameEvents.GameOver`

- 残りが1以上なら終了しません。
- 残りが0以下なら、先に終了フラグを立ててからGameOverを通知します。
- 同じ通知が繰り返されても、終了通知を重ねません。複数のControllerがあっても、共有GameOverを受けて終了済みになります。
- 既存の `PlayerController` はすでにGameOverを購読し、入力をDisabledにする実装を持っています。今回そのコードは変更していません。
- 結果画面は担当Cが `GameEvents.GameOver` を購読して表示する口です。今回、担当Cの画面遷移やUIは実装していません。
- `Time.timeScale` は変更していません。Animatorの再生を止めます。材質による微小な浮遊は継続します。

別シーンで試す場合は `GameOverSystem.prefab` を1個置けば、同じ共有イベントを受けられます。実際のプレイヤーが未配置のシーンでは、衝突による被弾までは発生しません。確認シーンではボタンから共有の被弾通知を流して経路を検証しています。

同じシーンでラウンドを再開する場合、各所有者が自分の状態を初期化します。B側は `GameOverController.ResetRound()` と各 `EnemyActionAnimation.ResetPresentation()` を呼びます。この2つはプレイヤーのHPや入力、スコアの初期化を代行しません。
