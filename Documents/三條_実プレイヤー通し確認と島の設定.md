## Unityで自分で確認する

### 1体で最後まで確かめる

1. Unityで上記プロジェクトを開く。
2. 上部メニュー **Hitofuri → Sanjo → Open Real Player Route Test** を選ぶ。
   同じシーンは `Assets/_Project/Scenes/Dev/Sanjo/PlayerIntegrationRouteTest.unity`。
3. Playを押し、Gameビューをクリックして入力できる状態にする。
4. 右側から影が1体出現する。近づいて攻撃姿勢と短い突進を行い、主人公に接触すると、画面上の `PlayerDamaged remaining=2` が出る。
5. 1回被弾したら、**左マウスボタンを押したまま D で右へ約8〜9m移動**する。目安は約1.3〜1.5秒。画面右端の島の縁には出ないようにする。
6. 左マウスボタンを離す。刀の位置から現在地へ斬り抜け、線上の影が右へ飛ぶ。画面の `EnemyHit` → `EnemyFell` → `WaveCleared 1` と、`Completed / pending=0 / alive=0` を確認する。
7. やり直しはStopして再度Play。ゲームパッドなら左スティックで移動、Southボタンを押して刀を置き、離して斬り戻す。

刀を置いてから約3秒経つと既存の自動斬り戻しも発動する。長く待ちすぎず、敵が線上にいる間に離す。接触したまま何もしない場合は被弾が進み、ゲームオーバーになる。

**Hitofuri → Sanjo → Open Real Player Test** を選んでPlayする。

灯喰らいの誘引範囲は基本10m × `GameContext.MeiStats.LureRadiusMultiplier`。範囲外では主人公を追う。斬り戻すと主人公へ戻る。

全員浮遊版を使用し、既存の歩行・走行素材は残した。出現中は約1.05秒追跡を待つ。主人公を狙い、距離2m以内になると自動で攻撃姿勢を再生する。0.2秒の予備動作後に0.25秒間、4m/sで約1m踏み込む。攻撃全体は1秒、終了後の待ち時間は1.1秒。値は各EnemyTuningで変更できる。

通常ウェーブは 1:影3、2:影3+灯喰らい2、3:盾2+影2、4:影3+灯喰らい2+盾2、5:影4+灯喰らい4+盾3。全30体を時間差で出す。

盾は最新の共有仕様どおり **正面では吹き飛ばない完全ガード**。通常の0.2倍で飛ばす設定ではない。斬り抜け自体は止まらず、後ろの影にも当たる。背面からなら盾持ちも飛び、初速に重さの倍率0.6が掛かる。

## GameEventsの連携

共有 `GameEvents.cs`、`ILaunchable`、Player/Mei/Feedback/UIのソースは変更していない。C#標準のstatic event、Raiseメソッドによる発行、OnEnableの登録とOnDisableの解除という形式を継続する。

| 出来事 | 発行元と連携 |
|---|---|
| 刀を置く | 実PlayerController → `GameEvents.RaiseSwordPlanted(position)` → 灯喰らいの追跡先を切替 |
| 接触被弾 | 実PlayerHealth → `RaisePlayerDamaged(remaining)` → GameOverControllerが0を判定 |
| 斬り戻す | 実PlayerController → `RaiseSlashStarted(info)` → 灯喰らいの追跡を主人公へ戻す |
| 命中 | 実PlayerController → 敵の `ILaunchable.Launch(velocity, slashId)` → `RaiseEnemyHit(info)` |
| 光の蓄積 | Enemy.Launch → `RaiseGlowChanged(enemy, ratio)` |
| 縁で停止 | Enemy → `RaiseEnemyTeetered(enemy)` |
| 場外落下 | Enemy → `RaiseEnemyFell(new EnemyFellInfo(slashId, position))` |
| ウェーブ開始・全滅 | WaveController → `RaiseWaveStarted(number)`、全予定出現＋全登録敵の落下後に `RaiseWaveCleared(number)` |
| 終了 | GameOverController → `RaiseGameOver()` → 実主人公の入力停止、敵と進行の停止 |

`EnemyHit` はLaunch後の結果通知。これを購読してLaunchを呼び直す処理はない。共有イベントの引数と署名を変えず、同じ一振りのslashIdを落下まで維持する。

今回の主経路の実測:

```text
0.580s  WaveStarted(1)
3.395s  EnemyMotionEvents.AttackStarted
3.800s  PlayerDamaged(2)
3.802s  SwordPlanted
5.294s  SlashStarted id=1
5.383s  GlowChanged 0.20
5.383s  EnemyHit id=1 velocity=(11.10,0,0)
6.906s  EnemyFell id=1
6.906s  WaveCleared(1)
```

ゲームオーバー検証は別の新品の実Playerインスタンスで接触被弾2→1→0を確認した。同期イベントのため、先に登録済みのGameOverControllerがPlayerDamaged(0)を受けてGameOverを流し、その後に観測者がPlayerDamaged(0)を記録する。このため実測ログではGameOver行が0の行の直前に出る。重複発行ではない。

主経路ではテスト側からLaunch、PlayerDamaged、EnemyHit、EnemyFell、WaveClearedを呼ばず、Input Systemの確認用ゲームパッドから操作した。主経路完了後の柵・追跡先の独立確認だけはHP処理を無効化した。最後のゲームオーバー確認では新しい実PlayerHealthを使用している。動画後半のこれらの独立確認を、主経路の続きの通常プレイと混同しないこと。

## Blenderの変更と現在の範囲

元の `DarkMeadowMap.blend` と `FloatingMeadowStage.prefab` を残し、別の `GameJamIsland.blend` を制作した。元のBlenderの島に対して水平1.2倍を基本に、岬と3か所のくぼみを加えた。Unityの床の実測範囲は約 **55.94×32.42m**。高さの小さな起伏も保持している。

Blenderの `Map_05_Fences` に2区間、各6枚の柵を制作。元座標の外周角度110〜145度、220〜250度、縁の約94%位置に置いた。支柱は約1.4m、横板は約0.65mと1.15mの高さ。`FencePanel_0_00`〜`0_05`、`FencePanel_1_00`〜`1_05` としてUnityへ書き出した。柵のない縁は落下できる。

主人公のモデルは担当者シーンにあったカプセルと刀のまま。新しい歩行・斬撃の骨アニメーションは追加していない。敵は既存の出現・防御・攻撃クリップとコードによる浮遊・吹き飛びを使用する。

敵の攻撃は「自動の攻撃姿勢＋踏み込み」で、ダメージは担当者の既存の接触判定。攻撃の特定フレームだけ当てる武器判定ではない。柵の回避は簡単な方向調整で、高度な経路探索は含めていない。GameOverは通知と停止までで、リザルト画面への遷移は他担当の受け口を使う。主人公自身の場外落下による敗北は今回の変更には含めていない。

追加・変更した全ファイルとGUIDは `実プレイヤー-全配置一覧.json`、共通コードとイベント形式の点検は `実プレイヤー-GameEvents形式の確認.json` に記録する。ブランチ作成、コミット、プッシュは行っていない。
