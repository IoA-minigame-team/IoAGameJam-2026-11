# 敵処理を調整するとき、最初に読む資料

2026年11月11日。対象は三條担当の敵・ウェーブ処理。

## 普段の調整では、まずこの3か所を見る

| したいこと | 調整する場所 |
| --- | --- |
| 敵の種類、出現数、間隔、出る場所を変える | Unityの **Hitofuri → Sanjo → ステージ・出現管理** |
| 敵の速さ、攻撃範囲、予備動作、踏み込み、復帰の速さを変える | `Assets/_Project/Data/Tuning/` の `ShadowEnemyTuning` / `ShieldEnemyTuning` / `WerewolfEnemyTuning` |
| 敵の当たり判定を変える | 各 `Floating...Enemy.prefab` のRootにある **CapsuleCollider** のRadius / Height / Center |

敵の見た目は `ReactionPivot` 以下、ゲーム中の座標とColliderはRootが持つ。見た目を傾ける処理で当たり判定まで傾けないために分けている。

`Werewolf` は見た目の名前。現在のゲーム上の役割は灯喰らい（`LampEater`）。

## コードを読む場合の役割表

スクリプトは `Assets/_Project/Scripts/` 内。実際のゲーム動作は次の順に読むと追いやすい。

| ファイル | そのクラスが担当すること |
| --- | --- |
| `Enemy/EnemyPursuit.cs` | 主人公と刀のどちらへ向かうかを選ぶ。追跡方向を計算する |
| `Enemy/EnemyAutoAttack.cs` | 攻撃の予備動作・踏み込み・終了・待ち時間を進める |
| `Enemy/Enemy.cs` | Rootの移動、吹き飛び、柵、地面、落下、slashIdを管理する |
| `Enemy/EnemyActionAnimation.cs` | 出現・攻撃・防御・吹き飛び・復帰の見た目を作る |
| `Enemy/EnemyMotionEvents.cs` | 上記の敵部品同士へ状態を通知する |
| `Game/EnemySpawner.cs` | 安全な位置から敵を出し、自分が出した敵の生存数を数える |
| `Game/WaveController.cs` | 出現予定の時刻・数・波番号・波の終了を管理する |

`EnemyTuning.cs` と `EnemyWavePlan.cs` は設定の入れ物。`EnemyStageTools.cs`、`...AssetSetup.cs`、`...PlayModeChecks.cs` はEditor専用で、出現管理・素材生成・自動検証を行う。ゲーム動作を理解するときは、まず上表の実行処理を読む。

主人公の被弾判定は主人公担当の `PlayerHealth`。敵の攻撃スクリプトはHPを直接減らさず、踏み込みによる実際の接触を主人公側が判定する。この修正でも接触ダメージの所有者は変更していない。

## 吹き飛びから攻撃再開までの順序

1. 主人公が `ILaunchable.Launch(初速, slashId)` を呼ぶ。
2. `Enemy` がRootを飛ばす。`Launched` を受けた表示は体を傾け、表示が処理中であることを `PresentationBusyChanged(自分, true)` で通知する。
3. 地上で止まると `Enemy.State` は `Idle` になり、`Recovered` を通知する。**これは移動が止まった通知で、見た目の復帰完了ではない。**
4. 表示は `Recovering` で体を通常姿勢へ戻す。この間は `Enemy.CanPursue` がfalseなので、追跡も自動攻撃も始まらない。
5. 体が戻り切ってから `PresentationBusyChanged(自分, false)` を通知する。
6. 次の更新で追跡・攻撃を再開できる。攻撃開始通知を受け、Attackモーションを再生してから踏み込む。

表示を無効化した場合も待機解除を通知する。表示部品がない敵を永久に停止させないため。通知には対象の `ILaunchable` を付け、別の敵の復帰で自分の待機が解除されないようにする。

攻撃範囲内でも、出現待ち、吹き飛び、復帰、停止中、ゲームオーバーでは攻撃を開始しない。攻撃の調整値は `AttackRange`、`AttackWindup`、`AttackLungeDuration`、`AttackLungeSpeed`、`AttackCooldown`。復帰の速さは `ReactionResponse`。

## 共有GameEventsとの境界

他担当との契約は既存の `ILaunchable` と `GameEvents` のまま。

- **Launchは命令**。主人公が初速を計算して一度だけ呼ぶ。
- **EnemyHitは命中結果の通知**。受け取った敵が再びLaunchしない。
- 敵は `GlowChanged`、`EnemyTeetered`、`EnemyFell` を通知する。落下まで `slashId` を保持する。
- 波の開始・終了は `WaveStarted(int)` / `WaveCleared(int)`。UIや銘の選択をウェーブ処理から直接呼ばない。
- 購読は `OnEnable` の `+=`、解除は `OnDisable` の `-=`。発行は `Raise...`。

今回追加した復帰待ちの通知は、B担当内の `EnemyMotionEvents.PresentationBusyChanged`。共有 `GameEvents.cs` や `ILaunchable.cs` の変更は不要。

## 今回のレビュー指摘と修正

| 指摘 | 原因 | 修正 |
| --- | --- | --- |
| 復帰中に攻撃姿勢なしで踏み込む | 軌道がIdleになると攻撃可能になり、表示側だけがAttackを拒否していた | 表示の完了通知まで、追跡・攻撃に共通の `CanPursue` を閉じる |
| Colliderを変更すると柵で止まる位置がずれる | 障害物判定が固定半径0.48の中心線レイだった | 実CapsuleColliderのRadius・Height・Center・Direction・Transformスケールから形を作り、CapsuleCastで調べる |

Colliderは当たり判定の大きさを持つ唯一の設定元にした。コードにもう一つの半径を置かない。吹き飛び中は接触ダメージを防ぐためColliderを無効にするので、その間に空になる `Collider.bounds` にも依存しない。

形を移動先へ調べるAPIは [Unity公式のPhysics.CapsuleCast](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/physics/capsulecast)。スケールの扱いも [Unity公式のCapsuleCollider編集処理](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/PhysicsEditor/CapsuleColliderEditor.cs) を照合した。

## 確認する方法

通常の確認は、**ステージ・出現管理 → 最新主人公を観察 → Play**。3種類の追跡と自動攻撃を見られる。中央の広い場所で敵を吹き飛ばし、地上停止後に体が戻ってから次の攻撃へ入ることを確認する。最初は接触被弾を停止しているので、繰り返し観察できる。

表示だけを確認する場合は **Hitofuri → Sanjo → Open Enemy Launch Test** を開いてPlayし、**Launch (stop)** を押す。これは実主人公の攻撃ではなく、吹き飛び表示用の確認シーン。**Teeter at edge** で縁の踏みとどまりと復帰も確認できる。

自動検証は `Game/EnemyReviewRegressionChecks.cs`。Play中の複製で、主人公が攻撃範囲内にいる復帰直後と、Colliderの大小・非均一スケール・中心位置変更を検証する。PrefabやTuningアセットへ検証用の値を保存しない。

修正前は27項目中14項目が失敗し、2件の指摘を再現した。修正後は同じ27項目すべてが通った。別途、既存の吹き飛び・踏みとどまり・停止・落下の検証も通過した。

最終的なUnity Play Modeの検証結果:

| 確認 | 結果 |
| --- | --- |
| 今回の2件の再現・回帰確認 | 27 / 27 PASS |
| 既存の吹き飛び・踏みとどまり・停止・落下 | 43 / 43 PASS |
| 三種追跡・盾ガード・刀誘導・ゲームUI | 40 / 40 PASS |
| 実主人公の斬り戻し→落下→波終了、銘倍率の受け取り | 30 / 30 PASS |
| 合計 | **140 / 140 PASS** |

自動検証の結果は `work/review-fixes/` に記録した。今回の変更は敵スクリプト5本、ウェーブのコメント1本、Editor専用の再現検証1本とこの資料。既存の `LatestPlayerHandoffChecks.cs` にも初回実行時の保存先フォルダ作成を追加した。

既存Prefab・Tuning・共有基盤・主人公処理は変更していない。以前からのローカル変更はそのまま残している。コミット・プッシュはしていない。
